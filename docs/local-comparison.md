# Локальное сравнение: запуск и проверенные результаты

Статус: WORKING_AND_TESTED на Android API 37 arm64 эмуляторе с двумя настоящими аккаунтами, Room и Python-сервером. Физический телефон в этой среде не подключён и не проверен.

## Подключение сейчас

Сервер запущен на ноутбуке с HTTPS/WSS, порт 8443. Проверены `/health` на loopback и LAN с проверкой CA.

- Эмулятор Android Studio: `https://10.0.2.2:8443`.
- Телефон в той же сети: `https://192.168.1.145:8443` — фактический IP ноутбука на момент проверки; при смене сети адрес нужно проверить заново.
- В профиле обоих приложений указать соответствующий адрес, затем зарегистрироваться/войти на сервер под разными логинами. Старый сохранённый HTTP-адрес имеет приоритет над новым BuildConfig: его нужно заменить в профиле.
- Для Bee2 нужен arm64-v8a. Установить новый debug APK, содержащий публичный локальный CA. Системную проверку сертификатов/hostname приложение не отключает; два Android-теста подтвердили отказ от другого самоподписанного сертификата.
- Инициатор находит логин друга, задаёт период и отправляет запрос. Второй принимает. Оба получают реальное пересечение публичных **занятых** 15-минутных UTC-слотов; приватные события исключены. Слоты объединяются в интервалы и обрезаются периодом. Это не поиск свободного времени и не пересечение с точностью до секунды.

## Повторный запуск

Из корня SecureCalendar, с уже установленными зависимостями `.venv`, сохранить прежние SECRET_KEY, DB_PATH и OPAQUE_SETUP_ENCRYPTION_KEY (если использовался). Не менять их на тестовые и не удалять SQLite.

```sh
.venv/bin/python -m server.run_local --lan-host 192.168.1.145
```

Команда запускает существующий `server.main:app` на `0.0.0.0:8443`. Для другой LAN-сети заменить --lan-host фактическим IP ноутбука. CA и приватные TLS-ключи хранятся в игнорируемой `.runtime/local-tls`, приватные файлы имеют права 0600. Существующий CA сохраняется при смене IP, обновляется сертификат сервера. Публичный CA копируется только в debug resources. При первом создании/смене CA пересобрать APK:

```sh
JAVA_HOME='/Applications/Android Studio.app/Contents/jbr/Contents/Home' ./gradlew :app:assembleDebug
curl --fail --cacert .runtime/local-tls/ca.pem https://127.0.0.1:8443/health
```

В текущей проверке TLS-процесс запущен с отдельной прежней integration SQLite из `.runtime`, а не пользовательской БД. Это не перенос регистраций из другого сервера: подключаться нужно к одному и тому же процессу/адресу сервера. Разрешить порт 8443 в локальном firewall для телефона. Локальная сеть/INTERNET должны быть разрешены Android. Сервер наружу публиковать не требуется.

Release не включает debug CA и по-прежнему требует нормальной настройки доверенного HTTPS endpoint. HTTP/WS debug доступен для диагностики, но не защищает от MITM.

- Независимая Python test-only арифметика подтвердила 122 SSWU суммы, включая особые входы, и четыре критерия Z=-11. Полный XMD/SSWU вектор также совпал на Android.
- 11 Python server tests passed. Предупреждения о deprecated FastAPI lifespan/TestClient остаются.
- JVM и итоговая APK-сборка: см. актуальный integration-report.md.

Профиль проекта использует опубликованные алгоритмы RFC 9380 с BIGN/BELT; это не зарегистрированный IETF ciphersuite и не независимо аудированная реализация. Native/JNI исходники и точные параметры доступны; утверждения о malicious security или полном аудите constant-time не делаются. Дополнительные продуктовые лимиты не введены; существующие технические ограничения памяти, длительности и relay rate limit остаются.
