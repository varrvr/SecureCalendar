# PSI с защитой от активного собеседника

> Действующая модель: [threat-model.md](threat-model.md). Пользователь доверяет серверу и подтверждённым собеседникам; требуется защита от MITM. Прежние требования malicious security ниже — исторические и больше не обязательны. Ограничения корректности HashToGroup и незавершённого PSI сохраняются.

## Обязательное требование

Пользователь выбрал защиту от собеседника, намеренно нарушающего протокол. Требуется published malicious-secure PSI, с privacy/correctness для честной стороны с допустимым abort. Обычный DH-PSI для semi-honest сторон не включается автоматически. Сервер остаётся relay; открытые интервалы, множества слотов и секреты ему не передаются.

## Что уже выполнено

Из upstream Bee2 `4341f7a5c300f8e6dc292559e671eb899d831433` собран отдельный source-backed JNI `libbee2mapping.so`. Официальный BAKE SWU-вектор совпадает на macOS и Android API 37 arm64. Проверены неправильные длины, нулевая/неканоническая точка и совместимость кодировки с прежним Bee2Crypto. Полные upstream tests проходят. Подробности сборки — `native/bee2-mapping/README.md`.

Это fixed-input map из СТБ 34.101.66, а не утверждение о random-oracle encoding или malicious-secure PSI. Wikipedia дана пользователем как обзор; её учебное сравнение хешей не переносится в приложение.

## Проверенные кандидаты и ограничения

1. Bee2 — набор криптографических примитивов и BAKE protocols, а не готовый malicious PSI engine. Источник: https://github.com/agievich/bee2 .
2. DKT10 — опубликованный malicious-secure ECC PSI: https://eprint.iacr.org/2010/469 . Рассмотрен код libPSI commit `1159df1fecad06570ec384d64ab0724d05b6905b`. В `libPSI/MPSI/DKT/DktMPsiSender.cpp` при `checkVal != proof` выводится `Bad sigma Proof`, но `throw` закомментирован. Эту конкретную реализацию нельзя объявить готовой защитой от активного клиента и подключить без исправления и атакующих тестов. Это замечание о проверенном коде, не опровержение статьи.
3. Кандидат на отдельный backend — https://github.com/ladnir/volepsi , commit `1ecfe796c661085f21d37c7945bba11e9f54e04d`. В исходниках есть malicious VOLE mode, проверки соли/seed и регрессионные тесты. Он исследуется **отдельно в .tools**, не добавлен в APK и не заменяет Bee2. Наличие режима/тестов ещё не означает независимого аудита.

## Принятое направление: только Bee2 и OPRF-PSI

Пользователь явно отклонил замену Bee2. VOLE не подключается; результаты исследования остаются историческими, а не планом интеграции. Присланы `oprf_КМ-text.pdf` (26 страниц) и `oprf_КМ-slides.pdf` (29 страниц). Разбор: `docs/oprf-materials-review.md`.

Реализована самостоятельная групповая часть HashedDH: маскирование, вычисление и снятие маски через Bee2. Она не подключена как готовый PSI: необходимы спецификация hash-to-group/finalization, полная DLEQ-проверка и обоснование всей конструкции PSI для активного противника, включая множество U.

## Обязательные критерии допуска

1. Реальные native-тесты пустого/частичного/полного пересечения, включая разные размеры и границы периода.
2. Искажение сообщений каждой фазы, salt/seed substitution, proof failures, replay/reorder, неправильный peer/session и disconnect должны завершаться отказом, а не SUCCESS.
3. Поддерживаемая Android arm64 сборка с воспроизводимыми исходниками и лицензиями; отдельная проверка выбранных native dependencies.
4. Сквозной тест двух Android-клиентов через настоящий Python relay без открытых слотов и без синтетического PSI результата.
5. Явная спецификация leakage: размеры множеств, время/число раундов и разрешённый output. Malicious PSI не удостоверяет, что пользователь действительно занят в объявленных им слотах.

До выполнения критериев production comparison остаётся BLOCKED. Включение не должно состоять в удалении PsiUnavailableException.


## Результат отдельной host-проверки кандидата

VOLE-PSI и его native зависимости собраны на macOS arm64 в изолированный prefix. Выполнены все семь тестов: malicious PSI, malicious OPRF, salt-order, seed rejection, Ribbon seed и оба abort cases. Все семь Passed, exit code 0. Воспроизводимый runner, JSON и очищенный от ANSI лог находятся в `research/psi-candidates/`. Это не аудит и не Android-проверка VOLE.

Действующий Android APK не содержит VOLE engine. Пользователь отклонил эту замену; дальнейшая реализация сохраняет Bee2.
